# 使用说明

## 图形界面（双击 LenovoOtaTool.exe）

### ① 查询 OTA 包

1. 选机型（自动带出默认 SN，可手动修改）
2. 填「当前版本」（从设备读取：`adb shell getprop ro.build.version.incremental`）
3. 点【查询下一版本】→ 列表显示：目标版本 / 大小 / MD5 / 下载链接
   - 或点【自动走链】→ 自动反复查询，把整条链路的每一跳全部列出
4. 选中某行 →【复制选中链接】/【打开链接】/【下载选中包】
   - 双击行 = 复制链接

### ② 自动走链提取（推荐）

| 字段 | 说明 |
|---|---|
| 机型 / SN | 下拉选择，SN 自动带出 |
| 起始版本 | 链的源版本，一般填设备当前版本 |
| 目标版本 | 想提取哪个版本；**留空 = 一路走到服务器没有下一版** |
| 基础源镜像目录 | 起始版本的 `<分区名>.img`；可点【从设备读取基础镜像】自动 dd（需 root） |
| 缓存目录 | 下载过的包自动复用，不重复下载 |
| 输出目录 | 最终分区镜像输出位置 |
| 要提取的分区 | 可多选，如 `init_boot`、`boot` |

点【▶ 自动走链并提取】后，工具自动执行：

```
查询链路 → 逐跳下载增量包 → 逐跳应用补丁 → 输出目标版本分区（含哈希校验）
```

**实测例（五代从 199 提到 236 的 init_boot）**

```
起始版本：TB323FU_CN_OPEN_USER_Q00020.0_A16_ZUXOS_2.0.12.199_ST_260812
目标版本：TB323FU_CN_OPEN_USER_Q00020.0_A16_ZUXOS_2.0.12.236_ST_260911
基础源镜像目录：放 199 的 init_boot.img
执行：199 →[211]→ 211 →[222]→ 222 →[236]→ 236
输出：init_boot.img  SHA256 = E8F94F7D…F94D（与官方 manifest 逐字节一致）
```

### ③ 手动提取分区

适用于已经自行下载好 OTA 包的情况：

1. 选择 OTA 包（zip）
2. 点【载入 OTA 包 / 列出分区】→ 自动解出 `payload.bin` 并列出全部分区（同时提示全量/增量）
3. 勾选要提取的分区
4. 增量包需在「源镜像目录」放入上一版本的同名分区镜像（全量包不需要）
5. 点【提取选中分区】→ 输出目录生成 `<分区名>.img`，并自动做哈希校验

## 命令行

```bash
# 查询下一版本
LenovoOtaTool.exe query --model TB323FU_CN --sn SN_请填你的序列号 --version <版本串>

# 自动走链查询
LenovoOtaTool.exe query --model TB323FU_CN --sn SN_请填你的序列号 --version <版本串> --walk

# 列出包内分区
LenovoOtaTool.exe list --zip ota.zip

# 手动提取
LenovoOtaTool.exe extract --zip ota.zip --out out --parts init_boot,boot --old <源镜像目录>

# 自动走链提取
LenovoOtaTool.exe auto --model TB323FU_CN --sn SN_请填你的序列号 \
    --start <起始版本串> --target <目标版本串> \
    --base <起始版本镜像目录> --parts init_boot --cache cache --out out
```

输出格式（query）：

```
<目标版本串>\t<大小>\t<MD5>\t<下载直链>
```

## 从设备读取基础镜像（需 root）

「自动走链提取」页的【从设备读取基础镜像】按钮会通过 adb 执行：

```bash
adb shell su -c 'dd if=/dev/block/bootdevice/by-name/<分区><槽位> of=/data/local/tmp/<分区>.img'
adb pull /data/local/tmp/<分区>.img <基础源镜像目录>/
```

槽位自动探测：`adb shell getprop ro.boot.slot_suffix`（通常 `_a`）。

这样可以把**设备当前版本**的分区镜像取出，作为链路转换的起点。

## 常见问题

**Q：查询返回「无下一版本」？**
A：① 当前版本串不精确（必须含日期后缀）；② 该版本已是该 SN 能拿到的最新版本；
③ 内测(beta/DF)链路需要该机型内测白名单 SN，普通 SN 查不到。

**Q：提取增量包时提示某分区未产出？**
A：该分区含内置引擎不支持的操作类型（如 `PUFFDIFF`），通常出现在
`system` / `vendor` / `system_ext`；也可能是源镜像版本不匹配。

**Q：提取出来的镜像哈希和官方不一致？**
A：99% 是源镜像版本不对。源的版本必须等于包内 `pre-build`（可用
`payload_properties.txt` 查看），而不是目标版本。

**Q：下载很慢 / 重复下载？**
A：设置「缓存目录」，下载过的包会按 URL 文件名缓存复用，并校验大小一致才跳过。
